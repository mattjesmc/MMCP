# Which tools answer without a client

GENERATED by `tools/headless-doc.mjs` from the bridge's `GET /tools` manifest - do not edit by
hand; regenerate. Captured from a live bridge at http://127.0.0.1:25599 on 2026-09-06.

Every tool declares an execution context (`ExecutionContext` in the toolkit, served as the manifest's
`context` column since 0.129.0). A suite that drives a DEDICATED SERVER - no client, no screen - can
be written against this table rather than discovered by trying:

| Context | Answers on | Toolkit tools |
|---|---|---|
| `server` | a loaded world, on either process | 66 |
| `any` | the bridge alone - before a world, and on a dedicated server | 10 |
| `client` | a game client; never present headless | 22 |

What the contexts mean, mechanically (`BridgeServer.dispatch`):

- **`server`** runs on the server thread and refuses with `no server running` until a world is loaded.
  On a dedicated server that is from boot; on a client, once a world is open.
- **`any`** runs inline on the bridge's own thread with no world needed - `ping`, the log, the launcher.
- **`client`** runs on the render thread. A dedicated server never REGISTERS these, so they are absent
  from its manifest rather than present and refusing; the MCP shim hides the same set from every
  headless role (`CLIENT_SURFACE` in `index.mjs`, which this column checks on every fetch).

`ping` reports `clientPresent` and `serverRunning` for the live answer; this table is the promise.
